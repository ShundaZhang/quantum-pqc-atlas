先拆开三个常被混用的词

量子计算用量子态执行计算；抗量子密码（PQC）仍运行在经典计算机上，目标是抵抗已知经典与量子攻击。量子密钥分发（QKD）是另一类需要专用物理链路的技术，不是 PQC 的同义词。

02 / THE MINIMUM QUANTUM MODEL

先理解量子计算
真正改变了什么。

只学安全工作需要的那一层：状态、门、测量、干涉、纠缠，以及算法对密码假设的影响。

01 / STATE

量子位是振幅，不是“同时试遍所有答案”

一个量子位写作 α|0⟩ + β|1⟩，测量概率由振幅的模平方给出。相位也重要：它决定后续操作能否发生干涉。

02 / CIRCUIT

门改变振幅，测量给出经典结果

H、X、CX 是入门足够的门。重复运行线路得到分布；一次测量不会读出所有叠加态的信息。

03 / SCALE

可运行小线路 ≠ 可破解现用密码

密码学相关的量子计算需要纠错、足够的逻辑量子位与大量可靠操作。不要把物理量子位数直接等同于破密能力。

INTERACTIVE / BELL CIRCUIT

点四步，看“纠缠”如何出现

两条线代表 q₀、q₁。观察概率分布由单一结果变为相关的 00 / 11。单一测量基的相关直方图并不足以证明纠缠；这里也不模拟真实设备噪声。

03 / THREAT MODEL

真正需要换的，
是哪一层密码？

从算法到系统资产，避免“量子计算会破坏所有加密”这种过度概括。

现有能力量子影响工程判断应对方向
RSA / (EC)DH公钥加密与密钥建立高 · Shor大规模容错量子机可威胁其数学基础；长保密期数据要考虑“现在收集、以后解密”。ML-KEM；在协议允许时考虑标准化的混合密钥交换。
RSA / ECDSA / EdDSA身份与数字签名高 · Shor证书、代码签名、固件更新和长期验证记录需要分别盘点。ML-DSA / SLH-DSA；按生态成熟度迁移。
AES / SHA-2 / SHA-3对称密码与散列不同 · GroverGrover 给无结构搜索带来平方根级加速，不等于对称密码立即失效；还须计入实现成本与参数。审查密钥长度和安全强度，不把它们与公钥问题混为一谈。
业务系统TLS / PKI / VPN / 软件供应链系统性算法替换还会触及消息大小、握手、证书、硬件模块、兼容性和回滚。先做资产清单与试点，再制定可测试的迁移计划。
时间判断

没有可信的“破密量子计算机会在哪一年到来”的确定日期。优先级取决于数据需要保密多久、替换需要多久、暴露是否可被事后利用。

THE CORE PRIMITIVE

KEM 与签名，各解决一个问题

KEM 让通信双方建立共享秘密，之后通常交给对称密码保护数据。签名证明消息来自相应私钥持有者并保护完整性。仅换 KEM，不会自动让认证、证书和软件签名抗量子。

⇄

07 / FROM PAPER TO PRODUCTION

真正困难的部分，
在系统边界。

把“换算法”拆成五个可检查的动作。不同协议与供应商的时间表必须单独验证。

01

发现

找到算法和密钥实际出现的位置：服务、依赖、硬件、证书与备份。

02

排序

按数据保密期、签名验证寿命、暴露面、迁移周期评估优先级。

03

试点

从可回滚的小系统测试互操作、尺寸、延迟与故障模式。

04

验证

核对实现与协议，测试认证、降级、防旁路和密钥生命周期。

05

替换

逐步部署，保留观测与恢复能力，持续跟踪标准和供应链更新。

LONG-TERM SECURITY

别漏了 TEE / 远程证明

如果系统依赖远程证明、固件签名或硬件根证书，量子风险不只在 TLS 握手。应把证据签名、证书链、验证服务和长期保存的证明记录一起纳入清单。

一次试点最少回答
  • 保护对象与攻击者是谁？
  • 哪条链路使用了旧公钥算法？
  • 客户端和服务端是否都支持新机制？
  • 失败会怎样降级或回滚？
  • 谁监测标准与实现更新？
